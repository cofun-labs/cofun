# Privacy

Cofun makes AI side panels for Chrome, each one an extension for a different kind of page. The extensions share one sign-in and one server (the worker): this page says what they do with your data, the same for every extension. What each extension reads in your browser, which hosts it sends data to, and what it keeps on your device is on that extension's own privacy page; the two pages together are its privacy policy:

- [Notico](extensions/notico/PRIVACY.md), for Notion

This page describes the worker deployed from `worker/` and the extensions built from this repository with their committed configuration. If you build an extension against your own deployment, the hosts are the ones you configure.

The short version: when you ask a question, the conversation, including what the extension read from your pages to answer it, goes to our worker and from there to an AI model that runs on Cloudflare. We do not store that content on our servers. The worker keeps your credits and a record of what each request cost, never what you asked or what the AI answered.

## Who receives your data

Each service below gets only what is listed for it. What the worker does with what it receives, and what it keeps, follows under [What the worker keeps](#what-the-worker-keeps).

- **Clerk**, which holds your account. Every Cofun extension signs you in on the same page: its "Sign in" opens `https://api.cofun.cc/login` in a normal tab. That page runs Clerk's sign-in code, loaded from Clerk's Frontend API (`clerk.cofun.cc`). That code also contacts other Clerk hosts: Clerk Protect (`cdn.protect.clerk.com`, and a host under `client.protect.clerk.com`), a check that the sign-in comes from a person and not a bot, and Clerk's image host (`img.clerk.com`), for the logos and avatars it shows. What you enter on the page (an email address, or a Google sign-in) goes to Clerk and to the sign-in provider you choose, not to our worker. Clerk holds your account: your email address, name, and avatar as the sign-in provider gives them. See [Clerk's privacy policy](https://clerk.com/legal/privacy). An extension shows your name, email address, and avatar from that account in its side panel. The worker verifies each request's session token with Clerk's public key, without calling Clerk, and uses only your Clerk user id from it; for the operators' admin page it also reads the token's `role`, which says whether the account is an operator's (for every other account it is empty).
- **Cloudflare**, which runs the worker ([Workers](https://developers.cloudflare.com/workers/), the code in [`worker/`](worker/)), and processes what passes through it; see [Cloudflare's privacy policy](https://www.cloudflare.com/privacypolicy/). It gets:
  - **Your conversation**, to run the AI model. The worker passes it to [Workers AI](https://developers.cloudflare.com/workers-ai/) through Cloudflare's AI Gateway and streams the reply back. Log collection is turned off for the whole gateway, and the cache for these requests, so the gateway does not keep your messages or the replies; it keeps request analytics (counts, tokens, cost) tagged with your Clerk user id and the extension the request came from.
  - **The address of a web page to read**, when an extension asks for one (Notico asks for an address its assistant chose to answer your question). The worker fetches it from Cloudflare, sending no cookie or credential, with a user agent that names Cofun: the site sees a request from Cloudflare, not from you, and shows what it shows anyone who is not signed in. For a page drawn by scripts, the extension can ask for it to be rendered instead: the worker has Cloudflare's [Browser Run](https://developers.cloudflare.com/browser-run/) load the address in a browser on Cloudflare, which runs the page's scripts and loads what the page loads. The worker returns the page's title and text to the extension.
  - **The query of a web search**, when an extension asks for one (Notico asks with a query its assistant wrote to answer your question, which may hold text from your Notion pages or the conversation). The worker sends it to Cloudflare's [Web Search](https://developers.cloudflare.com/web-search/), through the same AI Gateway as the model, whose log collection is off (a search, unlike a model call, can't turn it off by itself), so the gateway does not keep the query or the results; it keeps request analytics (counts, cost) and Cloudflare's billing record of the search. The worker returns each result's address, title, and a description of its page to the extension.
  - **A visit to the sign-in page.** Cloudflare, which serves the page, adds its Web Analytics script to it, loaded from `static.cloudflareinsights.com`: it tells Cloudflare that the page was visited, with the page's address (each step of the sign-in included), the page you came from, your browser and operating system, and how quickly the page loaded and responded.
  - **What the worker keeps and logs**, below: the credits database ([D1](https://developers.cloudflare.com/d1/)), the usage records (Workers Analytics Engine), and the worker's logs all live on Cloudflare.
- **[Ceramic](https://ceramic.ai)**, the search provider of Cloudflare's Web Search, always the same one: the query of a web search, to make it. Cloudflare lists Ceramic as keeping no data of the searches it serves (zero data retention).
- **The sites of the web pages read for you**: a request from Cloudflare for the page's address, as above, and, for a rendered page, requests to the hosts it loads from; never with a cookie or credential of yours.
- **[Stripe](https://stripe.com)**, when you buy credits with a one-time payment. The extension asks the worker for a checkout, and the worker asks Stripe to make one; the extension then opens Stripe's Checkout page (`checkout.stripe.com`) in a normal tab. Stripe sells the credits as the merchant of record, through its Managed Payments: everything you enter there (your email address, name, billing address, and payment details) goes to Stripe and to Link, Stripe's checkout and support service, not to our worker or the extension. See [Stripe's privacy policy](https://stripe.com/privacy).
  - To make a checkout, the worker sends Stripe your Clerk user id, the pack you chose (Cofun's price for it and how many 1,000-credit units), and the addresses of the pages Stripe sends you back to. Stripe keeps them with the payment.
  - Stripe tells the worker's webhook when a payment goes through, is refunded, or is disputed. The worker reads from it only your Clerk user id, the pack you chose, whether the payment went through, and the payment's Stripe reference (its PaymentIntent id); to check what was paid for, it asks Stripe for the checkout's items (which price, and how many). It does not receive your payment details.
- **[PostHog](https://posthog.com)**, which we use to see how the extensions are used. When a payment adds credits, the worker tells PostHog that a purchase was completed: your Clerk user id and the pack you chose (how many 1,000-credit units), and nothing else. It holds no amount, currency, or payment reference, nothing you entered at Stripe, and it tells PostHog not to work out a location from the request, which comes from the worker, not from your device. Each extension's privacy page says what usage data the extension itself sends to PostHog, and how to turn that off; this event comes from the worker, so that switch does not cover it.

The worker does not store or log your conversation, the address or text of a web page, or a search's query or results.

## What the worker keeps

- **Your credits.** Using the assistant costs credits, and every account gets free credits each week. The worker keeps them in a database on Cloudflare (D1), by Clerk user id:
  - each grant of credits you were given: how many, how many are left, when they were granted and when they expire, and whether they were the free weekly grant, credits an operator granted you by hand (with that operator's Clerk user id), or credits you bought (with the Stripe reference of the payment, and, if it was refunded or disputed, that it was taken back and when);
  - one record for each call to the AI model your questions made, whether it was answered or failed: when it started and ended, which extension it came from, the model, whether the reply was streamed, how it ended and why the model stopped, the number of input tokens (with how many the model read from its cache) and output tokens (and whether they are an estimate, for a reply that was cut short), and the credits it cost;
  - one record for each page rendered for you in Browser Run: when it was rendered, which extension asked, how it ended, the browser time it used, and the credits it cost, never the address or the page;
  - one record for each web search made for you: when it was made, which extension asked, how it ended, how many results it gave, and the credits it cost, never the query or the results.

  It holds numbers, times, the model's name, and those ids only, never what you asked or what the assistant answered. Grants, model calls, renders, and searches are kept without an end date, after grants expire too, as the record of what the account was given, asked of the model, and spent. Operators of the service can look at an account's credits by its Clerk user id, and grant it credits, and can total grants, model calls, renders, and searches across accounts and list accounts, by Clerk user id, with what each was granted and spent.
- **Nothing new to show you your own credits.** An extension asks the worker for the signed-in account's credits: how many are left, when they expire, and when free ones arrive; how many were used on each of the last 30 days; and, only when you open the history, every grant of credits you were given, the expired ones included (where it came from, how many, how many are left or went unspent, and the days it was given and expires or expired; never which operator granted it), and how many credits you used on each day, as far back as you have used the assistant. The worker works all of these out from the records above each time, for the signed-in account only. So that a day is a day on your clock, the extension sends how far your clock is from UTC with that request; the worker uses the number for the answer and does not store it, though it is part of the request's address in Cloudflare's request logs (below), as is the date or the place in the list a request for older history goes on from.
- **One usage record per chat request, per web page read or rendered, and per web search**, in Cloudflare Workers Analytics Engine, which deletes them after 90 days.
  - For a chat request: your Clerk user id, which extension the request came from, the model, whether the reply was streamed, the outcome, the finish reason, the number of messages, the size of the input in characters, the token counts (with how many of the input tokens the model read from its cache), the credits charged, and the duration. Never message or reply text.
  - For a web page: your Clerk user id, which extension asked, whether the page was fetched or rendered, the outcome (such as "ok" or why the page could not be read), the characters of text returned, the credits a render was charged, and the duration; never the address or the page.
  - For a web search: your Clerk user id, which extension asked, the outcome, the characters of the results' titles and descriptions, the credits it was charged, and the duration; never the query or the results.

## What the worker logs

Cloudflare keeps the worker's logs: the request logs Cloudflare records for every Worker (such as the time, URL, and status of a request), and what the worker writes to them.

- **Errors.** When something fails, the worker logs a short part of the error, so that if it quoted part of a request, no more than a short excerpt of it reaches the logs. The one error it logs whole is from writing a usage record (above), which holds nothing you asked and nothing from a page.
- **Credits granted by hand**: the operator's Clerk user id, the account's Clerk user id, the number of credits, and when they expire.
- **Purchases**: your Clerk user id, the credits, and the payment's Stripe reference; for a purchase taken back, its reference and why; for a payment that grants nothing, its Stripe reference and why.

## Changes and contact

This file is written by recipient, and by what the worker keeps and logs. It changes in the same pull request as a change that adds a recipient, a kind of data one receives, or something the worker stores or logs; its [history](https://github.com/cofun-labs/cofun/commits/main/PRIVACY.md) shows every change. Questions and reports: [open an issue](https://github.com/cofun-labs/cofun/issues). Report a security vulnerability privately instead, as [SECURITY.md](SECURITY.md) says.
